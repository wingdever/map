# 第十六章 行政区域 与 经纬线

> 状态：**编码完成，待本机验收**（2026-09-13）。

---

## 1. 需求（用户原话）

> 1. 添加编辑**行政区域**的功能，行政区域是一种**虚拟区域，不构成通行和访问的世界实体**。
> 编辑行政区域，行政区域是由**行政线**这种**虚拟线**构成的封闭区域。
> 属于地图的行政区域**显示功能**。
> 2. 添加显示**经纬线**的功能，**每 0.1 经纬度**显示，可在设置中**关闭开启，默认不显示**。

---

## 2. 关键概念：虚拟 vs 实体

这一章引入的不是"又一个区域类型"，而是一条**新的分类轴**：

| | 世界实体 | 虚拟 |
|---|---|---|
| **区域** | 道路 / 小区 / 建筑 / 阻隔 | **行政区域** |
| **线** | 界线 / 路线 | **行政线** |
| 含义 | 影响通行与访问判定 | 只在地图上表达"这是哪一片" |
| 寻路（M2） | 必须参与求解 | **必须跳过** |

所以模型里加了两个显式标志：

```dart
enum AreaType { …, administrative;  bool get isVirtual => this == administrative; }
enum LineKind { boundary, route, administrative;  bool get isVirtual => this == administrative; }
```

**为什么值得为它单独加一个 getter，而不是在寻路里 `if (type == administrative)`**：
行政区域如果不被排除，"凤岗镇"就会变成一个**不能穿越的巨型障碍**，
把整个镇封死 —— 这是那种"上线后才发现、但一眼看不出原因"的 bug。
把语义写进模型的 `isVirtual`，寻路只要按标志过滤，就不可能漏。
校验脚本里钉了一条断言：**参与通行判定的区域类型恰好 4 个，且不含行政区域**。

> **不需要 schema 迁移**：`area_type` / `lines.kind` 都是自由文本列、没有 CHECK 约束，
> 且所有读写走 `values` / `fromStorage`（未知值有兜底）。加枚举值的成本是零。

## 3. 编辑行政区域

工具栏新增 **「行政线」** 工具（与「界线」「路线」并列，各自独立）。
行政线是虚拟线，用「围合区域」把它们圈起来就得到行政区域。

**围合的类型一致性校验**（`commitRing`）：

| 情况 | 处理 |
|------|------|
| 只选行政线 | ✅ 表单**预选「行政区域」** |
| 只选界线/路线 | ✅ 照旧 |
| 两者混选 | ❌ 拒绝：「行政线和界线/路线不能混着围成同一个区域」 |

理由：混着围出来的区域**既不是障碍也不是行政区**，说不清它是什么 ——
"是不是虚拟"是个要么全真要么全假的性质。

顺带：用行政线围合时，表单标题会说明"这几条是**行政线**（虚拟），类型已预选「行政区域」"。

## 4. 显示：虚拟的东西就该看起来"轻"

| | 实体 | 虚拟 |
|---|---|---|
| 区域蒙层 | 填充 12% | 填充 **5%** |
| 区域边框 | 实线 2px | **虚线 1.5px** |
| 线 | 实线（界线 3.5px / 路线 2.5px） | **虚线 1.5px**（青色） |

虚线是"这是虚拟的、不挡路"最直观的表达。

地图左下角新增 **「行政区」开关**（与「店铺」并列），
**只在这类要素确实存在时出现** —— 没东西可藏就不占地方。

## 5. 经纬线网格

- 间距 **0.1°**（在凤岗—龙岗一带：纬差 ≈ 11.1 km、经差 ≈ 10.3 km）；
- **默认关闭**，设置页顶部「地图显示」里开关，**写进 `schema_meta` 持久化**；
- 拉远看方位用的参考网格 —— 放大到街区级本来就看不见它，这是它的定位；
- 每个刻度带标签（`22.7°N` / `114.2°E`），贴在**上边缘**（经线）与**左边缘**（纬线）。

### 5.1 两个实现要点

**（一）刻度必须用「整数下标 × step」，不能累加。**
0.1 在二进制里除不尽，累加到第 3 条就变成 `22.800000000000004` ——
标签会显示成怪数字、和"整刻度"对不上。校验脚本把这件事钉住了：

```
22.60~22.80 的纬线刻度: [22.6, 22.7, 22.8]
累加法对照: 22.800000000000004  vs  下标法: 22.8
```

**（二）做成 FlutterMap 的**子图层**，而不是用 `mapViewportProvider`。**
后者是防抖 300ms 的（为了不让拖动期间狂查数据库），网格跟着它走会明显滞后，
拖动时线会"粘"在原地。`MapCamera.of(context)` 每次相机变化都同步重建，
网格才跟得住手。（已确认 flutter_map 的 `MapInheritedModel` 包住了子节点，
自定义图层能拿到 camera。）

### 5.2 拆分：算法在 core，渲染在 features

刻度生成放在 `lib/core/graticule.dart`（纯 Dart，零 Flutter），
渲染在 `lib/features/map/graticule_layer.dart`。
拆开是因为刻度生成有两个容易出错的地方（浮点漂移、范围失控），
放在纯函数里才能**脱离界面验证**。

`kGraticuleMaxLinesPerAxis = 80` 是防御性的：万一初始化瞬间算出退化 bounds，
不至于一帧生成几万条线卡死界面 —— 过密就直接不画。

## 6. 显示偏好的持久化

新增 `lib/features/map/display_prefs.dart`，统一管三类显示开关：

| 偏好 | 默认 | meta 键 |
|------|------|---------|
| 经纬线 | **关** | `display.graticule` |
| 店铺标签 | 开 | `display.shops` |
| 行政区域 | 开 | `display.administrative` |

- 存在 `schema_meta` 表（复用已有的 `getMeta` / `setMeta`），**重启后仍生效**；
- 读取是"先给默认值、再异步读回来"——界面不等磁盘；
- 写入是 fire-and-forget，开关手感不等一次落盘；
- 原来 `edit_mode_controller.dart` 里的 `showShopsProvider`（内存态）已删除，
  统一收到这里。

| R-16-1 | **行政区域不做层级** | 现实里行政边界是省/市/区/镇多级的。现在是一层，靠名字区分。要层级得加 `parent_id`，等真有需要再说 |

## 9. 请在本机验收

```bash
cd ~/Projects/flutter/map
flutter pub get
dart analyze lib/          # 期望 No issues found!（0 error / 0 warning / 0 info）
flutter run -d linux
```

**A. 经纬线（默认关闭）**

1. 启动后地图上**不应该有**经纬线；
2. 点右上角齿轮 → 设置页最上面「地图显示」→ 打开**「显示经纬线」**；
3. 返回地图 → 应看到每 0.1° 一条细网格，带 `22.7°N` / `114.2°E` 这样的标签；
4. **缩放/拖动时网格应跟手**（不滞后），线始终压在整 0.1° 刻度上；
5. **杀掉 App 重开** → 经纬线仍然是开的（设置被记住了）；
6. 再关掉 → 默认关闭的状态也是记住的。

**B. 行政线 + 行政区域**

1. 进编辑模式 → 工具栏应有**「行政线」**（与界线、路线并列）；
2. 用行政线连出 4 条首尾相接的边围成一块地；
3. 切「围合区域」→ 依次点这 4 条行政线 → 底部按钮提示应能闭合；
4. 点围合 → 表单**类型已预选「行政区域」**，标题会说明这是行政线；
5. 确认 → 地图上出现**青色的虚线边界 + 很淡的填充**（一眼看出是虚拟的）。

**C. 混围被拒绝**

1. 用 3 条行政线 + 1 条界线（或路线）围一块；
2. 点围合 → 应提示「行政线和界线/路线不能混着围成同一个区域」，且**不落库**。

**D. 行政区显示开关**

1. 地图左下角应出现**「行政区」**小胶囊（只有在存在行政区域时才有）；
2. 点它 → 行政区域的蒙层与虚线边界一起消失；再点回来。

**E. 实体不受影响**

1. 道路/小区/建筑/阻隔四类区域、界线/路线两种线，渲染应和之前**完全一样**
   （实线、正常填充）；
2. 左下角「店铺」开关仍然管店铺标签。
