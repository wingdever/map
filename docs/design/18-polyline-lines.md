# 第十八章 折线：一条线可以拐弯

> 状态：**编码完成，待本机验收**（2026-09-14）。
> 上游：第十四章把线分成**界线 / 路线**；本章让"一条线"从**两点**变成**折线**。
> schema **v9**、备份格式 **v7**。

---

## 1. 需求（用户原话）

> 为**路线**添加**弯折**功能，即路线可能不是笔直的，而是除了两个端点外，
> 内部可能有多个**拐点**，这条**折线**才是该路在地图上的构成。
> 请在**数据结构**上完成这个转变。可以损坏上一版已经存储的数据。

---

## 2. 四个决策（2026-09-14 用户拍板）

| # | 决策 | 结论 | 为什么 |
|---|------|------|--------|
| D1 | 顶点怎么存 | **保留 `lines.start_point_id` / `end_point_id` 两列，另加一张拐点表 `line_bends`** | 起点/终点被大量代码依赖（组环、门的吸附、线的业务键…），留成列能让"这条线从哪到哪"仍然是**一次查询**就能拿到的事；拐点天然是"附加的、可空的"东西。迁移也因此退化成**建一张空表**（见 §3.2） |
| D2 | 哪些线能拐 | **三种线都行**（界线 / 路线 / 行政线） | 一堵墙拐个弯是常态；数据结构既然是折线，就没有理由只让路线弯。同一张表里加"这条线允不允许有内部点"的约束只会是长期负担 |
| D3 | 怎么画 | **连续点按逐段延伸 + 「完成」按钮结束**；拐点**仍然只吸附已有点** | 与"连线只吸附已有点"这条既有红线一致（见 §4.1） |
| D4 | 旧数据 | **无损转换**（老线 = 没有拐点的折线） | 迁移就是建表，一条数据都不用搬；用户给的"可以损坏"许可**没有用上** |

## 3. 数据模型（schema v9）

### 3.1 新表 `line_bends`

```sql
CREATE TABLE line_bends (
  line_id  INTEGER NOT NULL REFERENCES lines(id),
  seq      INTEGER NOT NULL,
  point_id INTEGER NOT NULL REFERENCES points(id),
  PRIMARY KEY (line_id, seq)
);
CREATE INDEX idx_line_bends_point ON line_bends(point_id);
```

| 约定 | 说明 |
|------|------|
| `seq` | **从 1 开始**，第 k 个拐点就是 `seq = k`。**0 是起点、末位 + 1 是终点** —— 它们不在这张表里，而在 `lines` 的两列 |
| 顶点总数 | `2 + 这条线在 line_bends 里的行数`；`ORDER BY seq` 就是**绘制顺序** |
| 一条线 = 折线 | `[起点, 拐点₁ … 拐点ₙ, 终点]`。**没有拐点的线就是两点直线** —— 老数据天生满足 |
| 为什么拐点也是 `points` 里的一等公民 | 拐点要能命名、能复用（同一个路口是好几条线的拐点）、能被吸附、能拖动 —— 那它就只能是点。用 JSON 数组存在 `lines.ext` 里的话，上面四件事一件都做不到 |

代码侧：

- `LineRow.bendPointIds`（有序内部顶点）+ `vertexPointIds`（完整顶点序列）；
- **`bendPointIds` 不是 `lines` 表的列**，读库时由 `AppRepository._attachLineBends` 用**一条** `IN (...)` 查询补齐（与 `AreaRow.lineIds` 完全同一套做法）；
- 写库分两条路：`insertLine`（点 + 线 + 拐点一个事务）与 `setLineBends`（覆盖式改形状）。`updateLine` **只**改 `lines` 表的列 —— 改名字与改形状是两种意图，混在一起的话一次改名就可能把拐点清空。

### 3.2 v8 → v9 迁移：只有两条建表语句

```dart
const List<String> userV9Statements = [
  'CREATE TABLE IF NOT EXISTS line_bends (...);',
  'CREATE INDEX IF NOT EXISTS idx_line_bends_point ON line_bends(point_id);',
];
```

**不动 `lines` 表、不搬任何数据。** 老线的拐点表是空的，而"没有拐点"的语义
正好就是它们本来的样子。这正是 D1 那个选择的最大回报：

| 方案 | 迁移内容 | 出错的机会 |
|------|----------|------------|
| 顶点全搬进新表（`line_points(line_id, seq, point_id)`，含起终点） | 建新表 + 逐行搬运 12 条线的顶点 + 重建 `lines` + 改所有读线的地方 | 多（沿用 v4 那套 新建→拷贝→DROP→RENAME） |
| **本方案** | **建一张空表** | 几乎没有 |

实测（`tool/checks/polyline_real_db_check.dart`，跑在用户真库的**副本**上）：
升级前后六张表的行数逐项相同（点 47 / 线 12 / 区块 2 / 关联 8 / 门 1 / 线上要素 1），
拐点表 0 行，`lines` 的列一个没动。

### 3.3 折线的几何收口在 `core/polyline.dart`

| 函数 | 干什么 |
|------|--------|
| `polylineOf(line, pointsById)` | 顶点 id → 坐标序列。**任何一个顶点查不到坐标就返回 null**（整条不画） |
| `pathLengthMeters` / `pointAtPathDistance` | 折线总长 / 沿程取样（超出两端夹住） |
| `projectOntoPath(p, path)` | 投影：最近的**段**、垂足、沿程米数、按总长的 `t`、到折线的距离 |
| `spanAlongPath(path, t, widthM)` | "中心 ± 宽度/2"那一段（墙体段渲染用） |
| `turnAngleDegreesAt` | 某个顶点的转角（详情/将来合并平缓拐点用） |

> **为什么必须收口**：第十八章之前，"一条线"在代码里到处都是 `(start, end)` 两个点。
> 线一旦能拐弯，这些地方会**悄悄把它拉直** —— 不报错、不崩溃，就是画错。
> 所以几何计算只准从这里拿结论，别处不许自己写 `startPointId → endPointId` 的数学。

## 4. 交互（编辑模式）

### 4.1 拉一条折线

1. 选「界线 / 路线 / 行政线」工具 → **点一个已有点** = 起点；
2. 继续点已有点 → 每点一个**延长一段**（那个点成为拐点），屏幕上实时画出草稿折线，
   并把起点/拐点/当前终点分别标出来；
3. 工具栏「撤销」= **退掉最后一个顶点**（不是清空整条草稿 —— 拐了五道弯的路
   点错最后一个点还得从头点一遍的话，这工具没法用）；
4. 「完成」落库（≥ 2 个顶点才可点），随即弹出线属性表单，标题里写明
   "这条线有 N 个顶点（起点 + N-2 个拐点 + 终点）"。

**拐点仍然只吸附已有点，绝不新建**（第十二章红线的延续）：

> 想在路上加一个弯，先用「标点」把那个拐角落下来。

理由是折线让这条红线**更重要**了：现在一次点按就可能凭空多出一个"看起来只是手抖"的
拐点，而每个拐点都永久留在数据里，让这条线的业务键、围合关系、店铺定位全部跟着变。
吸附不到时提示也不再是干巴巴的"附近没有点"，而是直接告诉他该怎么做：
`拐点也要先落成点：用「标点」工具点一下这里，再回来继续拉`。

### 4.2 改形状：不需要新工具

**拐点就是点**，所以：

- 「选择」工具下**长按拖动**那个拐点 = 改这条线的形状（沿用既有的拖动顶点能力）；
- 删掉那个拐点所在的点 = 这条线自动**摘掉这个弯**（并明确提示
  "这个点是 N 条线的拐点，已顺带摘掉：线还在，只是少了一个弯"）——
  如果不做这一步，删点之后那条线的几何会**画不出来**（`polylineOf` 返回 null），
  用户看到的是"我删了个点，那条路不见了"，那是静默的数据丢失。

线详情面板会说清 `折线 5 个顶点 · 全长 213 m`，并提示"拐点也是点：长按拖动它就能改形状"。

## 5. 折线牵动的每一处（本章的实际工作量）

| 位置 | 之前 | 现在 |
|------|------|------|
| `core/ring.dart` 组环 | 一条线 = 一条边（走线） | **按边建图**：每条线贡献 `顶点数-1` 条边，从任意边出发走到回到起点。拐点因此自动按顺序进入环里 |
| `core/hit_test.dart` 命中线 | 投影到首尾直线段 | 投影到**最近的那一段**（逐段比）；`LineHit.t` 改成**按总长**的归一化位置，并给出 `alongM`/`segmentIndex` |
| `checkRingClosure` | 端点度数 | **顶点度数**（拐点也是顶点）。判据与组环器**逐字对齐**（否则会出现"提示能闭合、落库组不出来"） |
| `appendLineToRing` | 端点相接 | **任一顶点相接**（拐点与别的线端点重合是正常画法），与组环器同一套规则 |
| `line_feature_layout` 定位 | 投影到 `(start,end)` | 投影到折线；`t` 按总长；宽度占比的分母改成**折线总长** |
| 渲染 `map_page` | `Polyline([a, b])` | 全部顶点；墙体段沿折线取跨度；门/店铺定位同源 |
| 编辑草稿层 | 只画起点手柄 | 画整条草稿折线 + 起点/拐点/终点标记；围合已选线也按全顶点高亮 |
| `adoptWay`（OSM 单要素带入） | **只取首尾两点** | **中间节点全部落成拐点** —— 以前带入一条沿街拐了五道弯的路，等于把它拉成一条横穿街区的直线 |
| 导出 `core/export.dart` | `LineString` 写死两个坐标 | 全顶点坐标 + `properties.bend_point_ids`（几何给人看、properties 给导入用） |
| 导入 `core/import.dart` | —— | 读 `bend_point_ids`；老文件（v6 及更早）没有该字段 → 空 = 直线 |
| 合并 `core/merge.dart` | 线键 = `kind + 两端点` | 线键加上**拐点坐标键**（拐点侧排序，于是正着画/倒着画同一个键）；无拐点时**保持老键格式**，所以拿一份 v6 老备份再导一次**不会翻倍** |
| 备份格式 | v6 | **v7** |

### 5.1 一个必须讲清楚的键设计（第十一章那一课的同款）

端点相同、**中间拐法不同**的两条折线（一条绕小区北面、一条绕南面），
如果线键只含端点，第二条在导入时会被判成"已存在"而**静默丢弃**。

这与第十七章"业务键必须带楼层"是同一类错误（那次是整层数据静默丢失），
所以本章的线键：

```
kind | 端点键(排序) | 拐点键(排序，';' 连接)
```

拐点侧排序是刻意的：折线是有方向的（`seq` 有方向），但**同一条折线倒着画
不该变成另一条线**。已验证：正/倒着画同键、拐法不同不同键、无拐点保持老键。

## 7. 爆炸半径与回滚

| 项 | 说明 |
|----|------|
| 破坏性操作 | **没有**。升级只建一张空表；老库、老备份都能照常读 |
