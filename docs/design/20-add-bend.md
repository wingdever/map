## 1. 需求（用户原话）

> 路网中，我选取了路线后，可操作选项应保留**改属性**和**删除**，
> 去除**加店铺**和**加墙体**，增加**加拐点**的功能。
> 此时会出现一个**跟随鼠标移动的拐点**，拐点会向路线上**最近两个点**形成新的路线，
> **会自动拟合**。**再次点击即可放置**该拐点。

---

## 2. 面板动作按图层归位

| 线类型 | 面板动作 |
|--------|----------|
| **路线**（路网） | 改属性 · **加拐点** · 删除 |
| **界线**（世界图） | 改属性 · **加拐点** · 加店铺 · 加墙体 · 删除 |
| **行政线**（行政区域） | 改属性 · **加拐点** · 删除 |

判据是**这条线属于哪一层**（`MapLayer.ofLineKind(kind)`，19 章新增的映射），
不是散在 UI 里的 `kind == boundary`。于是：

- 「加店铺/加墙体」只出现在**世界图**的线上 —— 路线面板再也不会问"这家店挂在哪条路上"；
- 「加拐点」**三种线都有**（2026-09-14 用户拍板）：形状操作与类型无关，
  一堵墙拐个弯同样常见。

映射与工具的一致性由脚本守着：**创建某种线的工具，必须就在那种线的图层里**
（`routeLine`∈路网、`boundaryLine`∈世界图、`adminLine`∈行政区域），
否则会出现"用甲层的工具画出来、却按乙层的规则给动作/配色"这种错位。

## 3. 「加拐点」模式

### 3.1 怎么用

1. 路网层点中一条路线（或直接在面板上）→ 点 **「加拐点」**；
2. 工具条换成一条橙色横幅：`加拐点：<线名>` + 「取消」，光标变成**十字**；
3. **鼠标在地图上移动** → 一个橙色菱形跟着走，同时**实时画出"插进去之后"的折线**
   （悬停菱形能看到"离原线多少米、这条路全长 ±多少米"）；
4. **点一下** → 拐点就放下了；**还留在这个模式里**，可以接着加下一个弯；
5. 「取消」（或切工具/切图层）结束。

### 3.2 "自动拟合"的准确含义

> 找离鼠标**最近的那一段**，把新顶点插在它的两个端点之间，其余部分一个字节都不动。

- 这是**插入**，不是**平滑**：不会顺手把附近的拐角磨圆 ——
  磨圆会悄悄改掉用户已经认可的形状，而"拟合"要回答的问题是
  "加了这个点之后这条路变成什么样"，不是"帮我把路修得好看点"；
- 预览画的就是**落库后的真实几何**（同一个 `polylineOf`）。
  这是这个功能的全部价值：用户看到的是结果，不是"一个点"；
- 悬停标签给出**绕路代价**（`+15.9 m`）—— 这也是骑手真正关心的信息。

### 3.3 为什么这是一个新"模式"而不是一个新工具

工具栏上的工具都是"**开始画一个东西**"，而「加拐点」是对**某一条具体的线**的操作 ——
入口只能在那条线的属性面板上（和「改属性」「删除」并列）。
所以它是 `EditState.bendTargetLineId`（一个状态字段），**不是 `EditTool` 的枚举值**：

- `EditTool` 的不变式（19 章）要求"每个工具至少属于一个图层"，
  而「加拐点」不属于任何图层 —— 硬塞进去会破坏那条不变式；
- 它也不能和别的工具并存：**"点一下地图"的含义被它占用了**。
  于是 `setTool` / `setLayer` / `cancelDraft` / `exit` / 进入记录模式
  都会顺手退出这个模式（`clearBendTarget`），`onMapTap` 也**优先**处理它。

### 3.4 一律新建点（这是那条红线的一个明确口子）

第十八章的红线是：**拉线只吸附已有点，绝不新建点**（防的是"连线时手抖凭空多出孤点"）。
而「加拐点」**一律新建一个点**（用户 2026-09-14 拍板），不吸附已有顶点 ——
因为这里的每一次点按都是**一次明确的插入意图**："我要在这条路上多一个顶点，就在这里"。
两者的区别不是技术细节，而是**意图是否明确**：

| 场景 | 每一次点按的含义 | 结论 |
|------|------------------|------|
| 拉一条新线 | "把这一段连到那个点上" | 吸附已有点；附近没点就提示先去标点 |
| **加拐点** | **"拐点就放这里"** | **新建点**（鼠标指哪就是哪） |

**代价与防线**：这个口子会让 `points` 表被"加拐点"写脏 ——

- 落点离**已有顶点** < 0.5 m 时**拒绝**并说明（那会造出一段长度为零的边，
  在地图任何缩放下都短于一个像素，而库里却永久多了一个顶点）；
- 每次点按最多新增 **1 行** `points`（不是每次鼠标移动）；
- 拐点是 `points` 里的一等公民（18 章），所以已经有的清理手段都适用：
  选中它 → 删除（线还在，只是少一个弯）、长按拖动改位置。

### 3.5 落点数据的两个细节

- 新点**继承这条线的楼层**（`line.floors`）：2 层画的路线，拐点也必须在 2 层 ——
  否则切到 2 层时这条线会因为"缺拐点坐标"整个画不出来（18 章的 `polylineOf` 语义）；
- 新点的**类别跟着这条线所属的图层**走：路线 → **路点**，界线/行政线 → **辅助点**
  （复用 19 章的 `MapLayer.defaultPointKind`，与「标点」工具同一套规则）。

## 4. 实现要点

| 位置 | 改动 |
|------|------|
| `core/polyline.dart` | `planBendInsertion(line, pointsById, at)` → `BendInsertion{bendIndex, preview, distanceM, addedMeters, tooCloseToVertex}`；`kNearVertexEpsilonM = 0.5 m` |
| `core/edit_layers.dart` | `MapLayer.ofLineKind` / `ofAreaType`（把"哪条线属哪层"收口到一处） |
| `features/editor/edit_mode_controller.dart` | `EditState.bendTargetLineId` / `addingBend`、`startAddBend` / `cancelAddBend` / `placeBend`；`onMapTap` 优先处理；各处 `clearBendTarget` |
| `features/map/map_page.dart` | 面板动作按图层给；加拐点模式下的横幅工具栏；`MapOptions.onPointerHover` 记录鼠标位置；`MouseRegion` 十字光标；加拐点模式下 Marker 让开点击 |
| `features/editor/edit_overlay.dart` | 目标线高亮 + 跟随鼠标的拟合预览（`ValueListenableBuilder` + 橙色菱形手柄） |

**为什么鼠标位置不进 `EditState`**：hover 每帧都触发，走 Riverpod 会把工具条、图层、
状态条全部跟着重建（肉眼可见的卡）。用一个 `ValueNotifier<GeoPoint?>` 只让预览那一层重画，
代价就只剩一条折线的 draw。

**`bendIndex` 必须用 `planBendInsertion` 给的**：顶点序列是 `[起点, 拐点…, 终点]`，
"插在第 i 与第 i+1 个顶点之间"等价于"插进拐点列表的下标 i" ——
自己算错位置**不会报错，只会画出一条形状不同的路**。
所以脚本里有一条"把 `bendIndex` 真的用一遍、再算几何与 `preview` 逐个坐标比对"的检查。

## 5. 验证

### 5.1 脚本（不是测试文件）

```bash
dart run tool/checks/bend_insert_check.dart ~/.local/share/com.example.map/map.db
```

**33 通过 / 0 失败**，实测数字：

- 插入位置：第一段附近 → `bendIndex = 0`；第二段附近 → `bendIndex = 1`（追加）；
  两点直线的老线 → `bendIndex = 0`；
- **把 `bendIndex` 用一遍再算几何**与 `preview` 逐个坐标相同（第一段、第二段各一条）；
- 绕路代价：横向偏 **5 m → +0.5 m**，横向偏 **31 m → +15.9 m**（偏得越远绕得越多）；
- 落在已有顶点上 → 标记"太近"并拒绝（离顶点 2 m 则放得下）；
- **真库副本**：拿用户真画的那条 **105 个拐点**的路线，按 `setLineBends` 的 SQL
  插一个新拐点 → 拐点数 105 → 106，`ORDER BY seq` 还原的就是插入顺序，seq 是 1..N 连续，
  起点/终点没被动过。

**A. 面板动作**

1. 编辑模式 →「路网」→ 用「选择」点中一条**路线** → 面板应只有
   `改属性 · 加拐点 · 删除`（**没有**加店铺/加墙体）；
2. 切到「世界图」→ 点中一堵墙（界线）→ 面板应有
   `改属性 · 加拐点 · 加店铺 · 加墙体 · 删除`。

**B. 跟随鼠标的拟合预览**

1. 点「加拐点」→ 面板收起，工具条变成橙色横幅 `加拐点：<线名>`，鼠标变成十字；
2. **移动鼠标**：橙色菱形跟着走，并且**整条线实时变成"插进去之后"的样子**
   （原来的直段会被拉出一个弯）；悬停菱形可看到
   `新拐点：离原线 x m，这条路全长 +y m`；
3. 把鼠标移到这条线的**另一段**上 → 弯会出现在那一段上（插到最近的那一段里）；
4. **点一下** → 拐点落下，横幅还在（可以接着加），并提示
   "已加拐点（这条线现在 N 个顶点，全长 +y m）"；
5. 连加两三个弯 → 每次都在鼠标处，形状跟着鼠标走；
6. 点「取消」→ 回到正常工具条；**再点中这条线 → 顶点数应已经增加**，
   而且切到别的楼层也不会消失（拐点继承了线的楼层）。

**C. 边界情况**

1. 鼠标移到**离某个已有顶点很近**（< 1 m）的地方 → 菱形变**红**，提示
   "离已有顶点太近，这里放不下"，点下去**不会**加（并给出说明）；
2. 加完拐点后，用「选择」长按拖动那个新拐点 → 形状跟着变（拐点就是点）；
3. 删掉那个拐点 → 提示"这个点是 1 条线的拐点，已顺带摘掉：线还在，只是少了一个弯"。

**D. 数据**

```bash
sqlite3 ~/.local/share/com.example.map/map.db \
  "select l.id, l.name, l.kind, count(b.point_id) as bends
     from lines l left join line_bends b on b.line_id = l.id
    where l.deleted_at is null group by l.id order by bends desc limit 5;
   -- 上面那些线的拐点数应当比加之前多
   select count(*) from line_bends b
     left join lines l on l.id = b.line_id
     left join points p on p.id = b.point_id
    where l.id is null or p.id is null;"   -- 期望 0（无悬空拐点）
```
