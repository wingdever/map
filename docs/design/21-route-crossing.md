# 第二十一章 换路口：围栏路两侧可以交换

> 状态：**编码完成，待本机验收**（2026-09-14）。
> schema **无变更**、备份格式**无变更**（`route_width` 是自由文本列，
> 加一个枚举值不需要迁移 —— 见 §5）。
> 上游：第十九章给路线加了「路宽」（围栏路是其中之一）。

## 1. 需求（用户原话）

> 为路线增加**换路口**这一类型，表示**围栏路的两侧可以交换**的行驶路口。

## 2. 四个决策（2026-09-14 用户拍板）

| # | 决策 | 结论 |
|---|------|------|
| D1 | 放在哪一层 | **加进「路宽」那 5 个 chip 里** —— 换路口成为第 6 种路宽（`RouteWidth.crossing`） |
| D2 | 它跟围栏路怎么连 | **一条横穿的短线，连接一往一来的两条围栏路**：它的两个端点分别落在两条围栏路上 |
| D3 | 校验强度 | **只警告不拦**：可以先把路口标好，回头再把那两条路标成「围栏路」 |
| D4 | 带什么属性 | 就是普通线的那几个（名字 / 备注 / 楼层 / 位置），**不新增属性** |

> ⚠️ 记录一下 D1 的取舍：把它做成"一种路宽"其实与"路宽"的语义有出入 ——
> 前 5 个值是"这条路是什么样的路"，而换路口是**路上的一处地点**（通常只有几米长）。
> 我原本建议做成"线上要素"（挂在某条路线上、像门挂在墙线上那样），
> 用户明确选择了路宽，于是**按用户的选择实现**，并在下面把"它与众不同的地方"
> 用契约写清楚（短、两端要接上、通常双向、有独立旗标）。

## 3. 模型

### 3.1 第 6 种路宽

```dart
crossing('crossing', '换路口', 0xFFC2185B, 3.6, '围栏路两侧可以交换的路口…')
```

| 项 | 值 | 理由 |
|----|----|------|
| 存储值 | `crossing` | 与其它 5 个同构（自由文本列，`fromStorageOrNull` 兜底） |
| 颜色 | `#C2185B` 玫红 | 与 5 种路宽都不同色 —— 它是"路口"，不是"一段路" |
| 线宽 | 3.6 px | 比小窄路（2.0）粗：一条换路口只有几米长，太细就看不见了 |
| 是不是桥 | 否 | 它在地面上，不画虚线 |
| 判据 | `RouteWidth.isCrossing` | 表单提示、连接校验、渲染都问它，别处不写 `== RouteWidth.crossing` |

**画法**：用「路线」工具画一小段横线，两个端点各点一下两条围栏路上的点
（一往一来各一条），然后在表单里把路宽选成「换路口」。
表单里会多一句提醒：换路口一般**双向**，所以「单向」不用勾。

### 3.2 接上了没有：`core/route_crossing.dart`

`checkCrossingLink(crossing, allLines, pointsById)` 回答"这条换路口接在哪几条围栏路上"，
判定端点接上的两种证据（任一成立即可）：

1. **共享顶点** —— 换路口的端点 id 就是那条围栏路的一个顶点（起点/终点/**拐点**）。
   这是画的时候"点了那个已有点"的结果，最强；
2. **坐标够近** —— 端点离那条围栏路的**折线** ≤ `kCrossingLinkToleranceM`（5 m）。
   手画时差一两米的情况；18 章之后围栏路多半是折线，所以按折线算距离。

两个容差是刻意的：

| 容差 | 值 | 作用 |
|------|----|------|
| 连接容差 | **5 m** | "算接上了"。高于手抖/ GPS 抖动，又明显小于一往一来两条车道的间距（3–8 m），不会把对向车道误判成接上 |
| 附近容差 | **30 m** | "旁边有围栏路"（≈ 一条街宽）。**用来区分两种完全不同的毛病**：旁边根本没画围栏路（得先去标路）vs 围栏路就在旁边、只是端点悬着（画的时候没接上）—— 这两种情况给用户的话不一样，混成一句他就不知道该干什么 |

判定结果会变成**一句给人看的话**（`CrossingLink.describe()`），四种情形：

```
✅ 两头都接上了：起点 → 线 #12，终点 → 线 #13
⚠️ 旁边 30 m 内没有「围栏路」：换路口要横穿一往一来的两条围栏路，
   先把这两条路的路宽标成「围栏路」，再画这个路口
⚠️ 旁边有围栏路（线 #12），但两个端点都悬着：起点离它 18 m、终点离它 24 m，都没接上
⚠️ 只接上了一头（线 #12）：另一头离最近的围栏路还有 1021 m
⚠️ 两个端点接在同一条围栏路（线 #16）上：一往一来按约定是两条线，
   接成一条容易把"换边"画成"绕圈"
```

> 写这句话时踩到一个坑：第一版报"另一头离最近的围栏路还有 `min(两端距离)`"，
> 接上的那头距离≈0，于是输出"**另一头**离最近的围栏路还有 **0 m**" ——
> 自相矛盾。必须报**悬着那一头**的距离。脚本里专门有一条断言守它。

### 3.3 只警告不拦

保存完线属性之后，`map_page._warnIfCrossingUnlinked` 检查一次，不合格就弹一句提示，
**保存照旧生效**。理由（用户拍板）：现实里"先看到路口、再确认那两条路是围栏路"
和反过来都很常见，拦下来只会逼用户来回改。

---

## 4. 渲染：短得看不见，所以给它一个旗标

一条换路口通常只有几米长，zoom 15 下不到 2 个像素 —— 光靠那条粉线
**既看不见也点不中**。所以除了按路宽上色（玫红 3.6 px）之外，
还在它的**中点**放一个旗标：白底玫红圈 + ⇄ 双向箭头（选中时变黄）。
旗标同时是这一小段线的可点区域（`onTap` 走与其它要素一样的 `passthrough` 规则）。

---

## 5. 为什么 schema / 备份都不用动

- `lines.route_width` 是 **v10 加的 TEXT 列、没有 CHECK 约束** → 加第 6 个值
  只是一段新的字符串，老行一个字不动（脚本在真库上核对：
  `fenced×3 / main×10 / narrow×8`，换路口 0 条）；
- 备份格式 v8 里 `route_width` 字段**已经存在** → 新值照原样带走，
  不需要升版本（升版本的判据是"字段形状变了"，不是"枚举多了个值"）；
- 老代码读含 `crossing` 的备份时会 `fromStorageOrNull → null`（未指定路宽），
  这是既有约定（未知枚举值一律降级，不报错）。

## 6. 验证

### 6.1 脚本（不是测试文件）

```bash
dart run tool/checks/crossing_check.dart ~/.local/share/com.example.map/map.db
```

**36 通过 / 0 失败**，实测数字：

- 容差边界：端点离线 **4 m → 算接上**、**6 m → 不算**；
- 四种判定各自的话术都验过（两头接上 / 只接一头 / 接在同一条线 / 旁边没围栏路）；
- **折线围栏路的拐点也算接点**（`connectedEnds == 2`）；
- **真实坐标**：拿用户真画的那条 104 拐点折线当围栏路跑判定，两个端点都共享它的顶点
  → 正确判成"接在同一条线上（绕圈）"；
- 真库现状（只读）：**围栏路 3 条 / 换路口 0 条**，
  `route_width` 分布 `fenced×3、main×10、narrow×8`，全部取值合法。

> 顺带一个发现：真库已经是 **schema v10**，而且用户已经标了 **21 条路线**的路宽
> （大马路 10、小窄路 8、围栏路 3）—— 上一轮的功能真的用起来了。

### 6.2 本机手工验收

```bash
cd ~/Projects/flutter/map
flutter pub get
dart analyze lib/          # 期望 No issues found!（0 error / 0 warning / 0 info）
flutter run -d linux
```

**A. 先把两条围栏路标出来**

1. 「路网」层画两条平行的一来一往的路（各拐一两个弯也行）；
2. 分别点中它们 →「改属性」→ 路宽选**围栏路** → 保存；
3. 地图上它们应当是青绿色（`#00897B`）。

**B. 画一个换路口**

1. 用「路线」工具，在路口处横着画一小段：**两个端点各点一下那两条围栏路上的点**
   （能吸附到已有顶点最好）；
2. 「完成」→ 表单里路宽选**换路口** → 下面会多出一句"换路口一般是「双向」的…"；
3. 保存 → 这条小横线应当变成**玫红粗线**，并且中点出现一个 **⇄ 旗标**；
4. 点那个旗标 → 应当选中这条换路口（面板显示 `路线 · 换路口 · 直线段 · 全长 x m`）。

**C. 没接上时的提示（只警告不拦）**

1. 在离两条围栏路都很远的地方画一小段 → 路宽选「换路口」→ 保存；
2. 应当**保存成功**，同时弹一句"换路口还没接好：旁边 30 m 内没有「围栏路」……"；
3. 再画一段"只有一头接上围栏路"的 → 提示应当是
   "只接上了一头（线 #N）：另一头离最近的围栏路还有 XX m"（**不是 0 m**）；
4. 把一条围栏路的路宽改成大马路，再保存刚才那个换路口 →
   提示应当变成"旁边有围栏路…但两个端点都悬着"或"只接上了一头"。

**D. 数据**

```bash

     group by route_width order by 1;
```
