# 第十三章 线上要素：店铺 / 墙体 / 门

> 状态：**编码完成，待本机验收**（2026-09-13）。
> 上游：第十二章的编辑模式里，线上只能挂「门牌」，且位置靠权重分配。本章把它做成一等公民。

---

## 1. 需求（用户原话）

> 在一条线上，可以添加**门牌、门和墙体**。
> 门牌去掉在线上的**偏移**属性、添加**中心坐标**属性。
> 将**权重**改为**宽度**属性。
> 将门牌更名为**店铺**，店铺增加属性**门牌号**。
> 渲染时不再依据权重逐个加载，而是首先根据**中心点**进行加载。
> 中心点的坐标不在线上时，去线上离该点最近的点作为中心点。

---

## 2. 旧模型的问题

第十二章的线上要素（门牌）是这样定位的：

```
t_i = (Σ_{j<i} w_j + w_i/2) / Σw        ← 按权重沿线"分蛋糕"
位置 = 线上 t 处，再按 side_offset_m 垂直偏移
```

三个说不通的地方：

1. **改一个门牌的权重，整条街上所有门牌都会挪位。** 权重是相对量，
   任何一处变动都会重排全局。用户只想调一下 12 号铺的门面宽，结果 1 号铺跑了。
2. **位置是"算"出来的，不是"量"出来的。** 现实里店铺在哪是测出来的，
   不是按比例分配的。
3. **权重同时承担了两个职责**：既当"宽度"，又当"排序/定位"。
   一旦定位不再用它，它才终于能干净地叫「宽度」。

## 3. 新模型

### 3.1 线上要素三种，两条表

| 要素 | 落在哪 | 为什么 |
|------|--------|--------|
| **店铺** | `entities`（`entity_type='shop'`） | 通用线上要素 |
| **墙体** | `entities`（`entity_type='wall'`） | 同上，一条线可以一段是墙、一段是栅栏 |
| **门** | `gates`（**独立表，不动**） | 带门禁类型 / 车型 / 时间窗 / 单向 / 台阶，是寻路的核心约束，不该和通用要素混在一起 |

所以「在一条线上可以添加 X」在数据上 = `entities`（店铺 + 墙体）+ `gates`（门），
在 UI 上则是工具栏里三个并列的工具，用户不用关心这个区别。

### 3.2 `entities` 的字段变化（schema v5）

| 字段 | 变化 | 说明 |
|------|------|------|
| `door_no` | **新增** | 门牌号（「12号」「3栋2单元」） |
| `center_lat` / `center_lng` | **新增** | **中心坐标** —— 渲染位置的真身 |
| `width` | 由 `line_weight` **改名** | 宽度（米）：店铺门面宽 / 墙体段长度 |
| `boundary_type` | **新增** | 墙体段的材质（复用墙/铁栏/河道…那套） |
| `side_offset_m` | **删除** | 不再有垂直偏移 |
| `entity_type` | `door` → `shop` | 门牌 → 店铺 |
| `line_index` | 保留 | **只用于列表稳定排序**，不再参与定位 |

### 3.3 定位规则（本章的核心）

```
1. 要素没有中心坐标 → 跳过（宁可这条不画，也不要随便找个位置糊上去）
2. 把中心坐标投影到所属线段上（垂足落在线段外时取最近端点）
3. 投影距离 > 0.5 m → 记为"已吸附"，UI 上给个记号
```

「中心点不在线上时取线上最近的点」正是第 2 步 —— 用的就是垂足投影。

`0.5 m` 这个 epsilon 是刻意的：GPS 快采的点几乎不可能精确落在线上，
但用户**手点线上**时应当被认作"就在线上"，否则每次保存都弹一句"已吸附"，很烦。

### 3.4 宽度用来画什么

既然宽度不再决定位置，它就得有个可见的用途，否则是个死字段。所以：

- **店铺**：在中心点两侧各展开 `宽度/2`，画出这段门面；
- **墙体段**：同一段区间画成一条粗线，颜色取材质色 —— 一条线上
  「一段砖墙、一段铁栏」从此可以分别标注。

## 4. 老数据怎么办（v4 → v5 迁移）

**这是本章风险最高的一步**：老门牌的位置是算出来的，新模型要求每个要素自带坐标。
如果不做转换，用户升级后**整条街的店铺会全部挤到线的起点**（`center` 都是 NULL）。

所以迁移分两段：

1. **SQL 段**（`userV5Statements`）：重建 `entities` 表，
   `line_weight → width`、`door → shop`、补新列；
   带 `point_id` 的常送点直接取锚点坐标（一条 UPDATE 就够）。
2. **Dart 段**（`AppRepository._backfillLineFeatureCenters`）：
   按**同一套老算法**把 `t = (Σ_{j<i} w_j + w_i/2) / Σw` 反算成经纬度。

为什么 Dart 段不写成 SQL 窗口函数：这段逻辑要长期和
`core/line_feature_layout.dart` 保持一致；写在 SQL 里没人看得懂，
而且算法一调整两边就对不上了。

> **已用真实数据验证**：造一个含 3 个老门牌（权重 2/1/1）+ 1 个常送点的 v4 库，
> 跑完迁移后 —— `door→shop`、`line_weight→width`、`side_offset_m` 已移除、
> 常送点坐标由 SQL 回填；再按 Dart 的回填公式算出的 `t = [0.250, 0.625, 0.875]`，
> 换算成坐标再走一遍新定位，**t 原样回来** —— 升级前后位置逐个对得上。

## 5. 渲染

| 要素 | 画法 |
|------|------|
| 墙体段 | 沿线的粗线（颜色 = 材质色），**不受"店铺"开关控制** —— 墙是线的形态，该一直看得见 |
| 店铺 | 中心点处**纯文字**标签：只有名字（门牌号 + 店名），没有图标、没有宽度 |
| 门 | 沿用第十二章的旗标（按门禁时间求状态着色） |

**店铺标签做成纯文字**（用户 2026-09-13 两次要求：先去宽度、再去左侧图标）：
地图上一条街可能挤十几家店，任何多余装饰都在加宽标签、加剧互相压盖，
而缩放后那些小字根本读不清。**位置本身已经说明"这是店铺"，不需要再画一个小图标。**

宽度、材质、类型、是否被吸附这些**编辑时**才关心的信息，都在详情面板里看
（`describeWidth` 会顺带把宽度算成"约占这条线的百分之多少"）。
Marker 盒子从 132×32 收到 112×28，给相邻店铺留出间距。

左下角「店铺」开关只控制店铺标签（一条商业街几十家店，全画会盖住底图）。
**墙体段不受它控制** —— 墙是线的形态，本来就该一直看得见。

## 6. 备份格式 v4

跟 schema v5 对齐：

- `entities` 的 `door` → `shop`、`line_weight` → `width`、去掉 `side_offset_m`、
  补 `door_no` / `center_lat` / `center_lng` / `boundary_type`；
- **中心坐标同时写进 GeoJSON 的 `geometry`（Point）**，这样导出的文件丢进
  QGIS 之类的工具能直接看到店铺点位；属性里再冗余一份，双保险。

**向后兼容**：v1/v2/v3 备份照常可读 ——
`EntityType.fromStorage` 把老的 `'door'` 映射成 `shop`；
老文件没有中心坐标的，导入后中心为空、渲染时跳过，在编辑模式里点一下线上位置即可补上。

**导入去重键**也换了：从「名字 + 所属线」改成
**「类型 + 名字 + 门牌号 + 所属线」** —— 同一条街上两家同名店靠门牌号区分，
两条街上的同名店靠线区分。

**A. 升级不丢位置（最重要）**

升级前先记下地图上现有门牌的位置，然后启动 App。期望：
**每个店铺都还在原来的位置**（迁移会把老的权重位置换算成坐标）。

```bash
sqlite3 ~/.local/share/com.example.map/map.db \
  "select id,name,door_no,round(center_lat,6),round(center_lng,6),width from entities;"
# 不该有 center_lat 为空、却挂在某条线上的行
sqlite3 ~/.local/share/com.example.map/map.db \
  "select count(*) from entities where line_id is not null and center_lat is null;"
```

**B. 三种线上要素**

1. 进编辑模式 → 画一条线（或者用已有的线）；
2. 工具切到 **「店铺」** → 点线上一点 → 填店名 `沙县小吃`、门牌号 `12号`、宽度 `6` →
   地图上出现 `12号 沙县小吃 6m` 小胶囊；
3. 工具切到 **「墙体」** → 点同一条线的另一处 → 选材质「铁栅栏」、长度 `30` →
   那一小段线变成 30 m 长的绿色粗线；
4. 工具切到 **「门」** → 点线上一点 → 照旧填门禁属性；
5. **一条线上同时有三样东西** = 需求达成。

**C. 中心点吸附**

1. 选中一个店铺 → 面板上应显示「中心点：22.71xxxx, 114.13xxxx」与「在线上的 x% 处」；
2. 拖动这条线**的一个端点**（选择工具里长按拖），让线不再穿过店铺 →
   店铺应该**留在原地不动**（它的中心坐标没变），只是吸附标记变成 ↺；
   ⚠️ 如果你期望的是"店铺跟着线动"，告诉我 —— 那是另一种设计（把中心点存成沿线比例）。

**D. 宽度**

1. 地图上的店铺标签**只有名字** —— 既没有 `6m` 后缀，**也没有左侧的小图标**；
2. 编辑店铺把宽度从 `6` 改成 `20` → 再选中它，**面板**里「宽度」那行应变成
   `20.0 m（约占这条线的 x%）`；
3. 编辑墙体段把长度从 `30` 改成 `80` → 地图上那段粗线明显变长
   （墙体的宽度仍然画出来，因为它就是那段墙的形态）。

**E. 备份往返**

设置页导出备份 → 文件里 `schema_version` 应是 **4**，
且 `entities` 的 feature 带 `geometry` 点坐标与 `door_no` / `width` 字段。
