# 第十九章 图层化编辑 与 路线的「路宽」

> 状态：**编码完成，待本机验收**（2026-09-14）。
> 上游：第十八章把线变成折线；本章把**编辑界面**按图层组织起来，
> 并纠正一处属性归属 —— **材质是界线的、路宽是路线的**。
> schema **v10**、备份格式 **v8**。

---

## 1. 需求（用户原话）

> UI 界面优化，编辑界面可以编辑**路网、世界图、行政区域**三种地图图层。
>
> 然后路网中的**路线**，其属性**不是边界材质和通行代价**。那是**界线**的属性，
> 路线的属性包括**路宽**：**围栏路、大马路、小窄路、骑行天桥、步行天桥**几种，暂时。

---

## 2. 四个决策（2026-09-14 用户拍板）

| # | 决策 | 结论 |
|---|------|------|
| D1 | 三层各放哪些工具 | **路网**＝路线＋路点；**世界图**＝界线＋区域＋门＋店铺＋墙体＋一笔画圈地＋辅助点；**行政区域**＝行政线＋行政区域；「选择」三层都有 |
| D2 | 图层是否也管"看得见什么" | **不管**。图层只决定能编辑什么；左下角显示开关保持现状（店铺 / 行政区域） |
| D3 | 路宽怎么落 | **新增 `lines.route_width`**（schema v10）；路线表单只编路宽；界线表单只编材质 |
| D4 | 界线的通行代价 | **去掉** —— 只留材质。"可骑行/仅步行"是路的语义，放在墙上说不通 |

## 3. 三个图层

### 3.1 划分依据：按"它描述的是哪个世界"分

| 图层 | 是什么 | 工具 | 颜色 |
|------|--------|------|------|
| **路网** | 你自己跑出来的路 | 选择、标点、**路线**、选取底图 | 蓝 `#1E88E5` |
| **世界图** | 现实世界的实体：围墙/铁栏、小区/建筑/河道、门、店铺、墙体 | 选择、标点、**界线**、**围合区域**、店铺、墙体、门、一笔画圈地、选取底图 | 蓝灰 `#546E7A` |
| **行政区域** | 虚拟的行政边界（寻路必须跳过） | 选择、标点、**行政线**、**围合区域** | 青 `#00838F` |

三层不是新造的数据概念，而是把已有数据**按它描述的世界**归三类 ——
所以**没有 schema 变更**（除了 D3 那条路宽）。

**跨层工具**（一个工具属于多层）是刻意的：

| 工具 | 属于 | 为什么 |
|------|------|--------|
| 选择 | 三层 | 切过去点不动东西的图层是坏图层 |
| 标点 | 三层 | 每层都要先落点才能连线；**落成哪一类点由图层决定**（见 §3.3） |
| 围合区域 | 世界图 + 行政区域 | 同一个动作，围出来是普通区域还是行政区域由**所选线的虚实**决定（`commitRing` 已有这套校验） |
| 选取底图 | 路网 + 世界图 | 主产物是**路线**（路网），顺带也能带 POI 成常送点（世界图） |

不变式（由 `tool/checks/layers_check.dart` 守着）：

1. **每个工具至少属于一个图层** —— 否则它是个点不到的死代码；
2. **每个图层都有「选择」** —— 否则切过去连东西都点不中；
3. `toolsOf(layer)` 与该工具声明的 `layers` 完全一致（不多不少）；
4. 每个图层的 `defaultTool` 确实在该图层里；
5. 工具的 `primaryLayer`（`layers` 的第一个）属于它自己的集合 ——
   **`layers` 里的顺序有意义**：第一个是它最常被用的那一层。

### 3.2 工具条：图层 → 工具 → 草稿

```
┌─────────────────────────────────────────────┐
│ [路网] [世界图] [行政区域]        ← 第一层：图层（单选，带色）│
│ [选择] [标点] [路线] [选取底图]   ← 第二层：该层的工具      │
│ 路网：自己跑的路……              ← 图层说明 ＋ 工具说明    │
│ 逐段点已有点拉出一条路线……                            │
│ [撤销] [取消]              [完成路线（5 个顶点）] ← 草稿操作 │
│ ▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬▬  ← 底部图层色条（余光可见）  │
└─────────────────────────────────────────────┘
```

三点设计取舍：

- **图层色条**贴在卡片底部：画图时眼睛在地图上，工具栏那行小字不会被逐字读，
  一条颜色带能让"我现在在哪一层"在余光里也成立；
- **切图层会丢掉草稿**，但**保留仍然可用的工具** ——
  一个画到一半的界线草稿跨到路网层毫无意义（而且"完成"会落出一条你此刻不看的那种线）；
  而「选择」在三层之间来回切时不该被重置；
- **进入编辑模式一律落回「路网 + 选择」**：一是骑手最常干的事就是画自己跑的路，
  二是落在画图工具上会让"我想看看"变成"我画了一笔"。

### 3.3 图层顺手决定的第二件事：默认落点类别

| 图层 | 「标点」落下的点 |
|------|------------------|
| 路网 | **路点**（`waypoint`）—— 落点几乎总是为了拼路线 |
| 世界图 / 行政区域 | **辅助点**（`auxiliary`）—— 拼线围合用的顶点 |

点表单的**预选类别必须与刚落库的那个点一致**，否则用户一按保存就把刚落的点悄悄改了类
（`map_page` 的 `PointFormRequest` 分支：编辑模式取图层默认，记录模式取 `recordKind`）。

### 3.4 区域类型也按虚实过滤

以前区域表单一律铺全部 5 个类型，于是用界线围出来的区域也能选「行政区域」，
选完落库时被 `commitRing` 拒掉 —— **让用户先选一个会被拒绝的选项是坏 UI**。
现在：虚拟（行政线围的 / 已存在的行政区域）只给「行政区域」，
实体只给 道路/小区/建筑/阻隔 四个。

判断依据是**正在编辑/正在围的东西**的虚实，不是当前图层 ——
在路网层点中一个已存在的行政区域，它当然还是行政区域。

## 4. 路线的属性：路宽（schema v10）

### 4.1 属性归属的纠正

| 线类型 | 拥有的属性 | 不拥有 |
|--------|-----------|--------|
| **界线** boundary | **边界材质**（墙/铁栏/绿化带/河道/施工/软边界） | 路宽、通行代价 |
| **路线** route | **路宽**（围栏路/大马路/小窄路/骑行天桥/步行天桥） | 材质 |
| **行政线** administrative | 都没有（虚拟线：既不构成墙也不构成路） | 两者 |

代码里这条规则是 `LineKind.hasMaterial` / `LineKind.hasRouteWidth` 两个 getter，
表单、详情面板、渲染全都问它们 —— 而不是各处自己 `kind == boundary` 硬写。

### 4.2 五种路宽（**第 6 种「换路口」见第二十一章**）

| 值 | 标签 | 颜色 | 线宽 | 说明 |
|----|------|------|------|------|
| `fenced` | 围栏路 | `#00897B` | 2.6 | 两侧有围栏/铁丝网的通道（小区间、工地旁） |
| `main` | 大马路 | `#1E88E5` | 3.4 | 主干道，双向、车流大 |
| `narrow` | 小窄路 | `#5C6BC0` | 2.0 | 城中村窄巷，能过但会车困难 |
| `bike_bridge` | 骑行天桥 | `#8E24AA` | 2.6 | 能骑上去的天桥/高架便道（有坡道）—— **虚线** |
| `walk_bridge` | 步行天桥 | `#EF6C00` | 2.0 | 只能推着走的步行天桥/台阶道 —— **虚线** |
| ~~`crossing`~~ | （换路口 → 21 章） | `#C2185B` | 3.6 | **第二十一章追加**：围栏路两侧可以交换的路口（实为"路口"而非"一段路"，见 21 章 §2） |

两个设计取舍：

- **"路宽"是类别而不是米数**：骑手判断"这条巷子我的车能不能进"用的是
  "窄巷 / 大路"这种经验分类，不是"3.5 米"；类别也更好在地图上配色区分。
- **天桥与路宽合成一根轴**：骑行天桥 vs 步行天桥就是"能不能骑上去"，
  这是骑手最在意的差别；两座桥用 `isBridge` 让渲染画**虚线**（它在空中，不在地面上）。
- **未指定不拦人**：`route_width` 可空，未指定就沿用老的统一蓝实线 ——
  不强迫用户先把每条路分类才能画路。真库现状：26 条路线全部未指定（这一章之前画的）。

### 4.3 `cost_class`（通行代价）：冻结，但不删

用户明确它不属于路线（放在界线上也说不通），所以**从表单里撤掉**了。
但列与数据都留着：

1. 老数据里有值（真库 12 条线里有 2 条 `cost_class='ride'`，升级到 v9 的库同理）；
2. 备份继续导出它，两机互导不丢信息；
3. **M2 寻路一定会重新需要"这条边好不好走"** —— 到那时按路由求值的需要重建
   （05 章已经因为时间窗踩过一次"先删后建"的教训）。

⚠️ 由此带来一个**必须小心的坑**：老代码在 `saveLineProps` 里写
`clearCostClass: costClass == null`，而表单现在不编辑它 ——
照旧写的话，**每次给一条老路线改名都会把它的通行代价悄悄清空**。
现在这个方法完全不碰 `cost_class`（并由 `tool/checks/layers_check.dart` 验证）。

### 4.4 迁移：一条 `ADD COLUMN`

```dart
const List<String> userV10Statements = [
  'ALTER TABLE lines ADD COLUMN route_width TEXT;',
];
```

- 老路线读出来 `route_width = NULL`（未指定），渲染按默认蓝；
- `cost_class` / `boundary_type` **一个字节都不动**。

> ⚠️ **`ALTER TABLE ADD COLUMN` 不幂等**：重复执行会报 `duplicate column name`。
> 所以迁移分支必须挂在 `if (oldV < 10)` 上（v6 那次的 `ADD COLUMN` 同理）。
> 这一条被脚本**验证**出来了，不是假设。

| `core/models.dart` | `RouteWidth` 枚举、`LineRow.routeWidth`、`LineKind.hasMaterial/hasRouteWidth`、`CostClass` 标注为**已冻结** |

| `core/export.dart` / `import.dart` | 备份 v8：带 `route_width`；老文件读成未指定 |
| `data/app_repository.dart` | 迁移分支 `oldV < 10` |
| `tool/checks/layers_check.dart`（新） | 迁移 + 路宽语义 + 图层不变式 + 属性归属 + 备份往返 |

**为什么把两个枚举放进 `core/`**：图层怎么分、哪个工具归哪层是**领域知识**，
不是某个页面的样式；而且放在纯 Dart 里，`tool/checks/layers_check.dart`
才能在纯 Dart VM 里验证那些不变式（`features/` 依赖 flutter，脚本 import 不进来 ——
`AppRepository` 也是这个原因没法从脚本驱动）。

### 6.2 本机手工验收

```bash
cd ~/Projects/flutter/map
flutter pub get
dart analyze lib/          # 期望 No issues found!（0 error / 0 warning / 0 info）
flutter run -d linux
```

**A. 三个图层**

1. 点「编辑」→ 工具条最上面一排应是 `[路网] [世界图] [行政区域]`，
   默认选中**路网**（蓝色），主按钮区显示「路网：自己跑的路……」；
2. 路网层下面那排工具应只有 **4 个**：选择、标点、路线、选取底图；
3. 点「世界图」→ 工具变成 9 个（含界线/门/店铺/墙体/一笔画圈地）；
4. 点「行政区域」→ 工具 4 个（含**行政线**、围合区域）；
5. 在**路网**层用「标点」落一个点 → 弹出表单里类别应预选 **路点**；
   切到**世界图**再落一个 → 预选 **辅助点**；
6. 画一条路线画到一半（点了 2 个点），**切到世界图** → 草稿应被清掉（不会跨层带走）；
   而如果当前是「选择」工具，切图层后**仍然是「选择」**。

**B. 路线的属性是路宽**

1. 路网层画一条路线 → 「完成」→ 弹出的表单里应看到 **路宽**（5 个 chip + 未指定），
   **看不到**「边界材质」也**看不到**「通行代价」；
2. 选「小窄路」保存 → 地图上这条线应变成**细紫色**；
3. 选「步行天桥」保存 → 这条线应画成**橙色虚线**；选「大马路」→ **粗蓝**；
4. 用「选择」点中这条路线 → 底部面板副标题应显示 `路线 · 小窄路 · 折线 3 个顶点 · 全长 xxx m`；
5. 点中一条**界线** → 面板显示的是 `界线 · 实体墙`（**没有**路宽）。

**C. 属性按类型分岔 + 不静默清数据**

1. 把一条界线在表单里改成「路线」→ 弹回路宽区；
   保存后**再改回「界线」** → 它原来的材质**还在**（不会被顺手清掉）；
2. 给一条**老路线**（升级前画的，`cost_class='ride'`）改名保存 → 查库时它的
   `cost_class` **仍然是 `ride`**（这一条最容易被写坏）。

**D. 区域类型按虚实过滤**

1. 世界图里用界线围一个区域 → 区域表单的类型里**没有「行政区域」**；
2. 行政区域层里用行政线围一个 → 类型**只有「行政区域」**（已预选）。

**E. 升级不丢数据**

```bash
sqlite3 ~/.local/share/com.example.map/map.db \
  "pragma user_version;                                   -- 期望 10
   select kind, count(*) from lines group by kind;         -- 与升级前一致
   select count(*) from lines where route_width is not null;  -- 升级后应为 0
   select count(*) from lines where cost_class is not null;   -- 期望 2（老的 ride 还在）
   select count(*) from lines where kind='boundary' and route_width is not null; -- 期望 0
   select count(*) from line_bends;                        -- 折线没被动过（你画的那些）"
```
