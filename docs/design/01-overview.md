# 凤岗·龙岗外卖「最后一公里」地图软件 —— 总体设计（v0.1 草案）

> 文档状态：**草案待协商**。本文件与 `docs/design/` 下其余章节共同构成设计文档。
> 阅读顺序：01 总览 → 02 架构 → 03 数据模型 → 04 交互与渲染 → 05 门禁·时间·寻路 → 06 离线·里程碑·风险。

---

## 1. 背景与问题

凤岗镇（东莞市）与龙岗区（深圳市）交界地带是典型的高密度骑手配送区：

- 存在大量**城中村**（雁田村、油甘埔村等）：握手楼密集、巷道狭窄、GPS 漂移大、门牌号混乱；
- 存在大量**大型封闭式小区**（大运城邦、龙岗万科翰邻城等）：只能从特定门进出，部分门有严格时间管制、门禁卡/人脸要求；
- 通用地图只把小区画成"一个点 + 几条路"，**完全无法表达**：

1. "面状障碍"——整片小区/村围是**不可穿越的高墙**，不是几条路能绕开的；
2. "门禁逻辑"——必须从特定出入口进入，且出入口有通行类型、门禁强度、开放时间、台阶等属性；
3. "界内可达"——进了门之后还要能在内部走到具体楼栋/单元/档口，这一段往往更绕。

因此本项目将「**封闭区块系统**」作为整个地图引擎的**最高优先级底层架构**：底图只做视觉参考，真正的导航语义由"封闭区块 + 出入口 + 界内路网"三层用户数据承担。

## 2. 目标与非目标

### 2.1 目标

| # | 目标 | 说明 |
|---|------|------|
| G1 | 提供可离线使用的凤岗—龙岗配送地图 | 跑单途中无信号也能看、能用 |
| G2 | 可绘制并管理封闭区块 | 圈地、命名、边界物理特性、生效开关 |
| G3 | 可在区块边界"打孔"定义出入口 | 门的位置吸附、属性完整可编辑 |
| G4 | 可绘制界内高精度路网与常送点 | 巷道、楼栋、单元、档口、停车点 |
| G5 | 按"当前时间+车型"正确回答"该走哪个门" | 时间管制是硬约束，不是装饰 |
| G6 | 在用户路网上做**全本地**的路径规划 | 不依赖任何在线算路服务 |
| G7 | 数据归本人所有、可备份迁移 | SQLite 本地存储 + 导出/导入 |

### 2.2 非目标（首版不做 / 明确不做）

| 项 | 说明 |
|----|------|
| 社交/众包共享数据 | 本人单机使用；未来如需共享另议（见风险 R 系列） |
| 账号体系与云同步 | 无服务器、无账号（个人备份优先） |
| 在线算路（高德/腾讯等商业路径） | 商业 API 无法叠加"高墙+门禁"语义，且需联网；本项目寻路全部本地完成 |
| 接单/抢单/订单管理 | 不是接单工具，是配送导航与地图记忆工具 |
| 车道级导航 / 实时交通 | 电动车配送场景不需要 |

## 3. 关键决策记录（已与需求方确认）

| # | 决策点 | 结论 | 影响 |
|---|--------|------|------|
| D1 | 运行平台 | **Android 手机优先**（Flutter 单工程，先只出 Android） | 单端验证快；iOS 后续按需 |
| D2 | 数据存放 | **本地优先、可全离线**（SQLite + 本地文件，无云端） | 全链路离线设计，见 02 章 |
| D3 | 底图方案 | **flutter_map + OSM 风格瓦片**，可离线缓存 | 无厂商 key/配额；渲染层纯 Flutter 自绘能力强 |
| D4 | 寻路策略 | **全本地寻路引擎**；路网来源 = **OSM 离线底网 + 自绘高精度层** | 需一桌面临近端工具（M2）做 OSM 矢量数据预处理 |
| D5 | 交通工具 | 外卖电动车为主，**末端常下车推行** | 代价模型区分骑行边/推行边/步行边，见 05 章 |
| D6 | 首版边界（MVP） | **编辑先行**：封闭区块 + 门 的可视化与编辑为第一交付物；寻路/导航放 M2 | 路网与数据有量之后导航才有意义 |
| D7 | 时间管制粒度 | 首版支持**每日固定时段**；表结构预留"按星期/节假日"扩展 | time_slots 采用可扩展 JSON，见 03 章 |
| D8 | 数据采集方式 | **纯手机端绘制 + "路过即记"快采**；不做桌面编辑器（先） | 手势编辑体验是 UX 重点，见 04 章 |
| D9 | 目的地类型 | 住宅小区楼栋 / 城中村门牌 / 工厂工业园 / 写字楼商铺 **都要支持** | 常送点实体需按类型建模（03 章） |
| D10 | 坐标系 | **全链路 WGS-84**（OSM 底图 + 设备 GPS 原生一致），不做 GCJ-02 偏移 | 规避国内厂商坐标偏移叠加错位；粘贴平台地址的 GCJ 处理列为开放问题（06 章） |

## 4. 用户与使用场景

### 4.1 用户画像

- 单人：本人，职业/兼职外卖骑手；
- 常在凤岗镇 ↔ 龙岗交界片区活动（雁田、油甘埔、大运城邦、翰邻城等）；
- 骑电动车，末端下车推行/步行送进门；
- 一天多高峰（午/晚），追求"少绕路、少被门禁卡住、少在小区里迷路"。

### 4.2 核心使用场景（用例）

| ID | 场景 | 现状痛点 | 本系统价值 |
|----|------|----------|-----------|
| U1 | 送大运城邦某栋 | 常走错门；北门 21:30 后关，绕到西门才发现 | 接单定位常送点 → 直接告诉你"此刻该走哪个门、几点关" |
| U2 | 送雁田村某巷某号 | 巷子迷宫、GPS 漂移、门牌乱 | 常送点带"巷道内路径 + 门牌照片/备注"，沿自绘路网点到点 |
| U3 | 送工厂/工业园 | 大门位置与导航显示不一致，车辆禁入需步行到门卫 | 工厂区块 + "仅到门卫/允许进入"型门 |
| U4 | 高峰期批量送 | 记忆靠脑，一天下来路线重复绕 | 轨迹记录与常送点复用（M3 起） |
| U5 | 首次/少去的小区 | 不熟，当场用通用地图找门 | 区块蒙层 + 门旗标 + 门禁时间状态实时可查 |
| U6 | 路过即记 | 想到要记的点了，停下掏出手机画 | 快采入口：一键按当前 GPS 打点 + 命名 + 类型 |

### 4.3 数据分层（全系统第一性原则）

```
┌─────────────────────────────────────────────┐
│  底图（视觉参考）  OSM 瓦片，离线缓存，不参与寻路 │
├─────────────────────────────────────────────┤
│  封闭区块 areas     高墙多边形：绝对不可穿越     │
│  出入口 gates       只在边界线上打孔，属性完整    │
│  界内路网           OSM 底网 + 自绘巷道/内部路   │
│  常送点/实体         楼栋、单元、档口、门卫、停车点 │
└─────────────────────────────────────────────┘
```

导航语义只来自后三层；底图仅为绘制时的地理参照与人的视觉锚点。

## 5. 覆盖区域（初版范围）

- 以凤岗镇与龙岗交界为核心，先铺 **雁田村、油甘埔村、大运城邦、万科翰邻城** 及周边骑手高频半径（约 3–5 km）；
- 框架支持任意扩展，数据"边用边加"：以区块/门/路网为增量单元，无全量录入压力；
- 底图离线包按行政区矩形区域下载（见 06 章），先下核心区，后续按需补。
