# 第六章 离线能力、里程碑与风险（v0.1 草案）

## 1. 底图与离线瓦片方案

### 1.1 瓦片获取与缓存

- 运行期：`flutter_map` 通过自定义 `TileProvider` 读取本地瓦片缓存（目录或 MBTiles），在线时可从 OSM 瓦片服务器补漏；
- 首次使用引导：选择区域包 → 下载核心区瓦片（见 1.3）→ 之后全离线可用；
- 瓦片缓存按 zoom 分级管理：zoom 14–17（导航与街区概览）必下；zoom 18–19（巷口细节）可选大包（体积大）。

> OSM 瓦片使用策略提醒：需遵守 OSM tile usage policy，个人/低流量下载一般可接受；若正式商用需换自托管瓦片源或矢量底图。列入风险 R-03。

### 1.2 区域包定义（初版建议）

| 区域 | 范围 | 用途 |
|------|------|------|
| 核心包（必下） | 凤岗—龙岗交界 ~ 4–6 km 半径 | MVP 高频区（雁田/油甘埔/大运城邦/翰邻城） |
| 扩展包（可选） | 凤岗镇全域 + 龙岗部分街道 | 跑远单备用 |

区域包用多边形/矩形裁剪下载，避免整城无用瓦片。

### 1.3 数据体积估算（OSM 栅格瓦片，供容量规划）

| zoom | 每 km² 约瓦片数(估) | 核心区(约 50 km²)估算 |
|------|---------------------|----------------------|
| 14 | 少 | ~百张 |
| 16 | 中等 | ~数千张 |
| 18–19 | 多 | 数万张（建议按需增量下载，不整包） |

> 具体数字待 M0 用真实区域跑一次下载统计后再精确（章节末尾留空待填）。瓦片以 png/jpg 压缩后平均 50–200 KB/张。

### 1.4 矢量数据（路由底网，M2）

- OSM 矢量路网由桌面工具裁剪 + 过滤后生成 `.graph` 文件（文本/紧凑二进制），导入 App；
- 文件目标 < 20–50 MB 量级（核心区过滤后），含节点、边、类别、one_way 与速度参考；
- 该文件与区块/门/自绘路网分层存储，导入更新时**不影响用户自绘数据**。

## 2. 数据备份与导入导出

| 功能 | 说明 |
|------|------|
| 自动备份 | 本地每日差异备份（保留 N 份），触发条件：应用退出/重要编辑后/每日定时 |
| 手动导出 | 一键导出为 **GeoJSON FeatureCollection + schema 版本 + 元数据** 的单个压缩文件（.mapexport.zip），可拷到电脑/网盘 |
| 恢复 | 从导出文件恢复；恢复前自动备份当前库 |
| 导入底网 | 导入 OSM `.graph` 底网（不影响用户层） |
| 迁移 | schema 版本迁移脚本保证旧备份可升级 |

导出内容覆盖：areas（含 boundary ring）、gates、points、lines、entities、settings。坐标 WGS-84 原样导出，未来要转给高德等需再叠加 GCJ 纠偏工具（见 R-04）。

## 3. 里程碑规划

### M0 —— 工程骨架（1 周内可评审）

- Flutter 工程初始化（Android）、flutter_map 集成、瓦片缓存 TileProvider、SQLite schema v1 与迁移骨架；
- geometry 原语实现 + 单测（吸附、点在多边形内、垂足）；
- 定位权限与基本 UI 框架、区块/门列表空态页。

**验收**：App 在 Android 真机启动，核心区底图可见，geometry 单测全绿。

### M1 —— MVP：区块 + 门 编辑与可视化（核心交付）✅ 已实现并验收

- 区块：圈地绘制/编辑边界/属性表单/删除；按 boundary_type 渲染蒙层与线型；
- 门：边界吸附打孔、门属性表单（含每日时间窗）、旗标渲染、拖拽微调、删除；
- 常送点/实体：快采（三步内）、列表、地图定位显示；
- 数据：审计/软删除/备份导出恢复；区块与门联动校验。

**验收（已达成）**：flutter analyze 0 issues；flutter test 76 全过；debug APK 构建成功。
能在手机上完整画出"大运城邦一期 + 北门/西门"，设置时间窗后旗标随系统时间变化；导出文件可恢复。

### M2 —— 寻路与最后一百米

- 桌面 osm_prep 工具 + 底网导入（底网数据源与 07 章导入子系统共用预处理管线）；
- 本地寻路引擎（A*/Dijkstra）+ 门禁时间引擎接入 + 区块不可穿越约束；
- 常送点→门→内部目标 综合工作流（05 章 §6）与到门状态卡；
- 导航文本/箭头呈现（骑行/推行/步行配色）。

**验收**：核心区任意两常送点间能出合理路线；关闭的门被正确排除并提示；可绕过需登记门。

### M2.5 —— OSM 开放数据底图导入（07 章；新增，可与 M2 并行/前置）

- M2a 桌面 osm_prep → `.osmapp`（路网/建筑/POI 精简字段；附核心区样例文件）；
- M2b App：schema v2 导入表（import_bounds/import_nodes/import_ways/import_pois）+ 导入/整体替换 + 导入层渲染与开关（与用户层零耦合，仅叠加显示）；
- M2c App：单要素点选带入（点选一条 OSM 路 → 初始 route_edge；点选一个 POI → 常送点；无批量转化）→ 进入既有编辑流程。

**验收**：见 07 章 §8（手机导入核心区样例、单要素带入后用户层出现可编辑边/常送点、重导不影响用户层数据）。

### M3 —— 数据增长与体验增强（可选迭代）

- 轨迹记录与"常走路线"复盘、门/路网修正建议；
- 平台地址粘贴解析（含 GCJ 纠偏，R-04）；
- 周几分别时间窗 UI（schema 已支持）；例外日/节假日；
- 夜间深色主题、通知提醒、批量瓦片管理优化。

## 4. 风险与开放问题

### 4.1 技术风险

| ID | 风险 | 影响 | 缓解 |
|----|------|------|------|
| R-01 | 手机端画多边形/拖拽精度有限 | 区块边界不贴合真实围墙 | 吸附+顶点微调+放大辅助；绘制可暂停放大再继续 |
| R-02 | GPS 在城中村漂移大 | 快采定位不准 | 记录 accuracy；支持拖拽校正与"线上吸附" |
| R-03 | OSM 瓦片使用策略 | 大流量下载受限 | 遵守 policy、限速、个人使用；后续评估自托管/矢量 |
| R-04 | 平台地址多为 GCJ-02 | 粘贴地址落点偏移几十米 | 提供 GCJ→WGS 纠偏转换（基于公开偏移算法）；提示手动校正 |
| R-05 | OSM 数据时效性（新小区/内部路缺失） | 底网不完整 | 自绘高精度层覆盖 + 修正记录（osm 修正边） |
| R-06 | 后台定位/省电 | 轨迹记录耗电 | 默认关，显式启用；节流采样 |
| R-07 | 数据量增长后绘制性能 | 图层卡顿 | 只渲染当前视口 + 抽稀 + 瓦片分级；实体按需加载 |
| R-08 | OSM 导入数据时效性/缺失 | 新小区/城中村内部路不准 | 导入层只读参考 + 采纳后用户层可改（07 章）；建筑/POI 分层导入 |
| R-09 | 导入包体积与手机导入耗时 | 大区域卡顿 | 桌面预处理抽稀 + 精简字段；事务批量 + 进度条（07 章 §7） |
| R-10 | ODbL 授权合规 | 公开分发需署名 | 个人自用合规；若未来公开，设置页展示数据来源与贡献者（OSM 署名要求） |
