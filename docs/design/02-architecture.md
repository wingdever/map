# 第二章 技术选型与总体架构（v0.1 草案）

## 1. 技术选型

### 1.1 技术栈总览

| 层 | 选型 | 理由 |
|----|------|------|
| UI 框架 | Flutter（Android 优先） | 既定选择；单端 MVP 验证 |
| 地图渲染 | `flutter_map`（Leaflet 风格 widget 地图） | 纯 Flutter、无厂商 SDK 锁定；Polygon/Line/Marker 自定义图层自由度高；离线瓦片缓存成熟 |
| 底图来源 | OSM 栅格瓦片（在线拉取 + 本地 MBTiles/瓦片缓存离线） | 无 key、无配额；渲染为 WGS-84，与手机原生 GPS 一致，**无坐标偏移** |
| 本地存储 | SQLite（`drift` 或 `sqflite` + `sqlite3` FTS5 可选） | 关系模型适合区块/门/路网拓扑；事务保护编辑 |
| 数据交换格式 | GeoJSON（导出/导入）、自定义 JSON schema | 通用、可审计、可迁移 |
| 路径规划 | 自研本地引擎（A* / Dijkstra on 自建图） | 见 05 章；不依赖在线服务 |
| OSM 矢量路网预处理 | 桌面端小工具（Dart CLI 或 Python）生成"路由底网"文件 | 手机端不做全量 OSM 解析，减轻负载 |
| 状态管理 | `Riverpod` | 编辑状态机 + 异步数据层清晰 |
| 定位 | `geolocator` / `location` | Android 前台/后台定位权限按需 |

> 可选后续：`maplibre_gl`/矢量底图 —— 仅在需要更高底图细节时再评估，不阻塞。

### 1.2 关键取舍说明

1. **为什么不用高德/腾讯 Flutter 插件**：它们把地图渲染放在原生侧，自定义"高墙多边形 + 门上旗标 + 编辑吸附"需要大量 platform channel 胶水，且自带 GCJ-02 偏移、必须联网；而本产品 80% 的价值在用户自绘层，不在底图。flutter_map 让我们**完全掌控绘制层**。
2. **OSM 底网 ≠ OSM 瓦片**：瓦片只是视觉底图；可寻路的"底网"是**另一份数据**——从 OSM 矢量数据里过滤出可通行道路（M2 桌面工具预处理），生成含节点/边/类别的路由文件，供本地寻路引擎使用。自绘高精度层覆盖底网更新不及时的小区内部路/城中村巷。
3. **坐标统一 WGS-84**：手机 GPS 输出即 WGS-84，OSM 亦为 WGS-84，二者直接叠加无偏移。将来若粘贴平台地址（多为 GCJ-02）需做坐标纠偏，见 06 章开放问题。

## 2. 总体架构

### 2.1 分层架构图

```
┌─────────────────────────────────────────────────────────────┐
│  Presentation 层（Flutter widgets）                          │
│  地图视图 | 编辑工具栏 | 区块/门/实体面板 | 表单 | 设置页      │
├─────────────────────────────────────────────────────────────┤
│  交互/状态层（Riverpod）                                     │
│  - 编辑状态机（区块绘制中 / 门打孔中 / 常送点快采 / 浏览）      │
│  - 选择状态（选中区块/门/实体 → 详情/编辑）                    │
│  - 手势与吸附（tap / drag / snap 逻辑）                       │
├─────────────────────────────────────────────────────────────┤
│  领域逻辑层（纯 Dart，可单测）                                │
│  - 几何引擎：点线面、点在多边形内、点线投影、线线求交、buffer   │
│  - 门禁时间引擎：time_slots 求值 → 门状态                     │
│  - 路由底网构建（M2）与路径规划引擎（M2）                      │
│  - 常送点/轨迹服务                                           │
├─────────────────────────────────────────────────────────────┤
│  数据层                                                      │
│  SQLite（区块/门/实体/底网/常送点/元数据）                     │
│  文件系统（离线瓦片 MBTiles、OSM 底网文件、导出 GeoJSON）       │
├─────────────────────────────────────────────────────────────┤
│  平台/基础设施                                               │
│  定位服务 | 文件访问 | 通知（门状态提醒可选）                  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 模块职责

| 模块 | 职责 | 关键接口/说明 |
|------|------|---------------|
| `map_view` | 底图 + 图层叠加渲染 | 图层顺序见 04 章；支持离线瓦片源 |
| `editor` | 绘制/编辑状态机与手势 | 区块、门、路网、常送点各自的编辑流程（04 章） |
| `geometry` | 几何原语 | `pointInPolygon`, `projectPointToSegment`, `segmentIntersectsSegment`, `simplify` 等 |
| `gate_time` | 门禁时间求值 | `evaluateGateStatus(gate, DateTime, vehicleType) → GateStatus` |
| `routing`（M2） | 寻路 | 自建图 A*/Dijkstra；门约束集成（05 章） |
| `storage` | SQLite DAO / 迁移 / 备份 | 见 03 章 |
| `tiles` | 瓦片下载与离线缓存 | 区域包管理（06 章） |
| `osm_prep`（桌面，M2） | OSM 矢量 → 路由底网 | 独立 CLI，产出 `.graph` 文件 |

## 3. 数据流

### 3.1 编辑时（写路径）

```
手势事件(tap/longPress/drag)
  → editor 状态机（含吸附决策：点吸附 / 线段吸附 / 捕捉模式）
  → 修改领域模型（暂存多边形、门候选点…）
  → 渲染层刷新（预览蒙层/预览旗标）
  → 用户确认 → storage 事务提交 → 撤销栈记录
```

### 3.2 浏览/导航时（读路径，M2 起）

```
当前 GPS/选择目标
  → 装载相关区块+门+路网（按空间范围惰性加载）
  → 门禁时间引擎：算出此刻各候选门状态
  → 寻路引擎：在"高墙不可穿、门按状态开放"约束下求路径
  → UI：路线 + 门旗标 + 提示文案（"走北门，22:00 关闭"）
```

## 4. Android 平台关注点

- **定位权限**：前台定位（跑单过程中使用）为主；后台定位仅当启用轨迹记录（M3）时按需申请，默认关闭；
- **离线运行**：所有核心功能不依赖网络；无信号时瓦片来自本地缓存；
- **存储**：瓦片包与数据库放在应用私有目录或 `Android/obb`（大包可选），避免用户误删；
- **省电**：绘制/编辑场景常亮可选；不做常驻后台。

## 5. 推荐的 Flutter 目录骨架（供 M0 参考）

```
lib/
  main.dart
  app/            # app 壳、主题、路由
  features/
    map/          # 地图视图、图层、相机
    editor/       # 区块/门/实体编辑状态机与手势
    areas/        # 区块列表/详情/表单
    gates/        # 门列表/详情/表单
    entities/     # 常送点与实体
    settings/     # 离线包、备份、关于
  core/

    time/         # 门禁时间引擎
    storage/      # SQLite DAO、迁移、导出导入
    routing/      # (M2) 底网与寻路
  shared/         # 常量、枚举、DTO
```
