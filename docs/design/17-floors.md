# 第十七章 楼层（等高）

> 状态：**编码完成，待本机验收**（2026-09-13）。
> 上游：第十五章做的「楼梯口」门类型，就是为这一章留的钩子。

---

## 1. 需求（用户原话）

> 为点、线、面增加**等高**功能，可以**指定层数，默认一层**，然后可以添加 2、3 层等。
> 表示**参与构成其它楼层**的地图要素。
> 然后当用户查看某区域的**第二楼层**，就会把**在等高属性中包含 2** 的地图要素显示出来。

---

## 2. 模型：楼层是一个**集合**，不是一个层号

```
points.floors  TEXT NOT NULL DEFAULT '[1]'   -- JSON 数组，如 [1,2]
lines.floors   TEXT NOT NULL DEFAULT '[1]'
areas.floors   TEXT NOT NULL DEFAULT '[1]'
```

为什么是集合：**一堵承重墙、一根柱子、一部楼梯是贯穿多层的** ——
它在 1、2、3 层都存在。用单个层号表达不了。
反过来 "只在 1 层和 3 层"（2 层挑空）也需要集合。

于是判定就一句话：

```dart
bool visibleOn(int floor) => floors.contains(floor);
```

### 2.1 三条硬约束

| 约束 | 为什么 |
|------|--------|
| 集合**非空** | 一个"哪层都不属于"的要素永远不会显示，那是数据错误而不是状态。移除最后一层时自动回到 `[1]` |
| 解析失败 → 回到 `[1]` | 坏数据当作"1 层"比当作"不存在"安全得多（后者会让要素凭空消失） |
| 存储用 JSON 数组 | 与 `tags`/`ext` 同一套风格；将来要支持 0 层 / 负层（地下）也不用改列类型 |

---

## 3. ⚠️ 最容易丢数据的地方：业务键必须带楼层

同一栋楼的 **1 层与 2 层足迹常常完全重合**。而备份合并的业务键原来是纯几何的
（第十一章：`kind|点A|点B`）。

**不带楼层会怎样**：导入一份含"1 层墙 + 2 层同位置墙"的备份时，
第二条墙会被判定为"已经存在"而**整层丢掉** —— 静默、无提示、
而且用户要到切到 2 层时才发现少了一堵墙。

所以三个键都加上了楼层：

```
点：  "22.7100000,114.1300000@1"    vs  "...@2"
线：  端点键本身带楼层 → 线段键天然按层区分
面：  "3栋|22.7150,114.1350@1"      vs  "...@2"
```

**线上实体（店铺/墙体）自己没有楼层字段，身份继承锚点**：
如果实体键用地面层、锚点键用 2 层，导入时 `pointIds[key]` 查不到，
实体的 `point_id` 会被静默丢掉。所以键用**锚点点的楼层**。

校验脚本端到端钉住了这件事：

```
同坐标不同层: 22.7100000,114.1300000@1  vs  22.7100000,114.1300000@2
两层同足迹导入 → 点 4 线 2        ← 两条线都进来了
```

## 4. 交互

### 4.1 楼层条（地图右侧常驻）

```
   ▲
   2      ← 橙字（在地面层以上）
   层
   ▼      ← 在地面层时禁用
```

做成**常驻竖向控件**而不是藏在设置里：切楼层是看地图时的**高频动作**
（楼上楼下对照着看）。也正因为常驻，"我现在在第几层"一直摆在眼前 ——
这很重要，否则用户会以为"我画的墙丢了"，其实只是切到了 2 层。

状态条里也会带一句 `缩放 17.0 · 2 层 · 区域 1 · …`。

**不做持久化**：如果上次退出停在第 3 层，下次打开会看到一张几乎空白的地图，
而用户完全不知道发生了什么。每次启动回到地面层是"意外最小"的选择。

### 4.2 表单里的楼层选择器

```
楼层（等高）   这个点参与构成哪些楼层
[1层] [2层] [3层] [＋加层]
```

- **先选后点**：点层号 chip 就把这个要素加进/移出那一层；
- **候选层号自动摊开到"当前最高层 + 1"** —— 想加第 2 层时第 2 层已经在眼前，
  不用先点一次「加层」；要加到第 8 层就连点「加层」把范围摊开；
- 当前正在查看的那一层会带一个 👁 记号；
- 下方一句话回显：`参与构成 1、2、5层`（不连续时会标出来）。

### 4.3 新建要素落在哪一层

**默认 = 当前正在查看的那一层。**

用户说的是"默认一层" —— 在最常见的情况（当前就在 1 层）就是这个行为；
而当你切到 2 层再画墙时，墙落在 2 层才符合直觉
（否则画完立刻看不见，还得回头把它改到 2 层）。

**一笔画圈地**会把楼层一并传给它自建的顶点与边线 ——
否则在 2 层圈出来的区域，边线却只在 1 层，一切到 2 层就只剩填色没有边界。

## 5. 显示过滤的范围

| 要素 | 过滤依据 |
|------|----------|
| 点 / 线 / 面 | 自己的 `floors` |
| 店铺 / 墙体段 | 它们所属**线的** floors（渲染时跟着线一起过滤） |
| **门** | 它吸附的**线的** floors |
| 没挂线的门（老数据） | 任何楼层都显示 —— 它没有可跟随的层，宁可多画也别让它消失 |

> **门没有自己的楼层字段**：用户这轮只要求给点/线/面加。
> 门跟随它所在的墙是合理的一阶近似（墙只在 1 层，墙上的门自然不该出现在 2 层）。
> 需要"同一个门通向多层"时，门自己加 `floors` 即可。

## 6. 迁移（v7 → v8）

三条 `ALTER TABLE ADD COLUMN`，**不需要重建表**：

```sql
ALTER TABLE points ADD COLUMN floors TEXT NOT NULL DEFAULT '[1]';
ALTER TABLE lines  ADD COLUMN floors TEXT NOT NULL DEFAULT '[1]';
ALTER TABLE areas  ADD COLUMN floors TEXT NOT NULL DEFAULT '[1]';
```

`NOT NULL DEFAULT '[1]'` 会把已有行**自动填成"只有地面层"** ——
正好是老数据应有的语义（它们本来就都在一层里）。

> **已用真实 SQLite 验证**：v7 库迁到 v8 后行数不变、
> 三张表的已有行的 `floors` 全是 `[1]`；全新 v8 建库的默认值也逐列核对。

## 7. 备份格式 v6

点/线/面的 feature 加 `floors`，写成 **JSON 数组**（`[1,2]`）而不是字符串 ——
导出文件是给人看的，数组比 `"[1,2]"` 好读也好手改。
导入侧同时容忍数组、字符串、以及老文件根本没有这个字段（→ 地面层）。

## 9. 取舍与未做

| ID | 项 | 说明 |
|----|----|------|
| R-17-1 | **楼层是全局的，不是"每个建筑自己的层"** | 现在"第 2 层"是全地图统一的。要"某栋楼有自己的楼层列表（含 B1、夹层）"是另一套设计，等真有需要再说 |
| R-17-2 | 只支持 ≥ 1 层 | 模型（`FloorSet`）本身支持任意整数（含 0 / 负层），只是选择器没暴露 —— 免得先猜一套地下层的交互 |
| R-17-3 | **门没有自己的楼层** | 跟随所属线（见 §5） |
| R-17-4 | 切到没有要素的楼层 = 空白地图 | 状态条会显示层号，但没做"这一层还没有东西"的空态提示 |
| R-17-5 | 改楼层的要素再导入旧备份会产生重复 | 与"改名字"同类（第十一章 §5.5 已记录）：楼层进了业务键 |
| R-17-6 | 旧的 `test/` 更加失效 | 按 `AGENTS.md` §1 不修 |

**A. 楼层条**

1. 地图右侧应有一条 `▲ / 1 / 层 / ▼` 的竖向控件；
2. 在地面层时 `▼` 应**禁用**（不给掉到 0 层）；
3. 点 `▲` → 变成 2 → **地图上原来 1 层的要素应当全部消失**
   （因为它们都还只在 1 层），状态条显示 `2 层`；
4. 点 `▼` 回到 1 层 → 要素回来。

**B. 把要素加到第 2 层**

1. 进编辑模式 → 选一个点或线 → 「改属性」/「线属性」；
2. 表单底部应有**楼层（等高）**：`[1层][2层][3层][加层]`；
3. 点 `[2层]` → 它变成选中态，下方文字变成 `参与构成 1-2层`；
4. 保存 → 点 `▲` 切到 2 层 → **这个要素仍然可见**（1 层的其它要素消失）；
5. 再点 `▼` 回 1 层 → 它也在。

**C. 新建落在当前层**

1. 切到 **2 层**，进编辑模式画一条界线（或圈一个区域）；
2. 保存 → 它应该**立刻可见**（因为在 2 层）；
3. 切回 1 层 → 它应当**消失**。

**D. 上楼的场景（这一章的意义）**

1. 在 1 层画一栋楼的轮廓（区域）与几堵内墙；
2. 切到 2 层 → 地图应为空；
3. 在 2 层画 2 层的内墙（外墙可以直接复用 1 层那几条？—— 不能，
   因为它们在 1 层。正确做法是把 1 层外墙的楼层改成 `1-2层`）；
4. 于是：改过楼层的外墙在两层都能看到，只在 2 层的墙只在 2 层看到。

**E. 升级不丢数据**

```bash
   select count(*) from points where floors is null;      -- 期望 0
   select floors, count(*) from areas group by floors;    -- 老数据应全是 [1]

```
